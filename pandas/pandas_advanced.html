Window Functions
SQL's OVER(PARTITION BY ... ORDER BY ...) in Pandas. If you're doing this with groupby + merge loops, I will find you.
The Mental Model
Core idea: A window function computes a value for each row using a sliding window of neighboring rows — without collapsing the DataFrame. GroupBy collapses rows. Window functions don't. Burn that distinction in.
RANKING
Rank within group: .rank(), .cumcount()
RUNNING TOTALS
Cumulative ops: cumsum(), cumprod(), cummax()
LAG / LEAD
Prev/next rows: shift(1) / shift(-1)
ROLLING
Fixed window: rolling(n).mean(), rolling(n).std()
EXPANDING
Grows from start: expanding().sum()
EWMA
Exponential weight: ewm(span=3).mean()
Ranking within groups (SQL: ROW_NUMBER / RANK)
❌ The Amateur ApproachWRONG
# Merging back just to add a rank column. Criminal.
ranks = df.groupby('dept')['salary'].rank(method='dense', ascending=False)
df2 = df.merge(ranks.rename('rank'), left_index=True, right_index=True)
✓ Direct AssignmentCORRECT
# transform returns same-index Series. Assign directly. No merge needed.
df['salary_rank'] = df.groupby('dept')['salary'].rank(method='dense', ascending=False)
df['row_num']     = df.groupby('dept').cumcount() + 1  # 1-indexed row number per group

# TOP-N per group: top 3 earners per dept
top3 = df[df['salary_rank'] <= 3]
Lag / Lead + Running Totals
shift(), cumsum(), rolling()
# ALWAYS sort first or your lag/lead is garbage
df = df.sort_values(['user_id', 'date'])

df['prev_purchase']  = df.groupby('user_id')['amount'].shift(1)   # LAG
df['next_purchase']  = df.groupby('user_id')['amount'].shift(-1)  # LEAD
df['cum_spend']      = df.groupby('user_id')['amount'].cumsum()

# Rolling 7-period average per user
df['rolling_7'] = (
    df.groupby('user_id')['amount']
      .rolling(7, min_periods=1)
      .mean()
      .reset_index(level=0, drop=True)  # drop the group level from index
)
transform vs agg — the most important distinction
transform broadcasts back to original shapeMEMORIZE THIS
# agg collapses rows
dept_avg = df.groupby('dept')['salary'].mean()        # shorter Series

# transform keeps same row count as df — assigns directly
df['dept_avg']      = df.groupby('dept')['salary'].transform('mean')
df['salary_vs_avg'] = df['salary'] - df['dept_avg']
TOPIC 02 / 10
MultiIndex
Hierarchical indexing. Most people fear it. You will own it. The secret: always know which level you're targeting.
Creating a MultiIndex — 3 ways
from_tuples / from_product / set_index
# 1. from_tuples
idx = pd.MultiIndex.from_tuples([('A',1),('A',2),('B',1)], names=['group','id'])

# 2. from_product — all combinations (powerful)
idx = pd.MultiIndex.from_product([['A','B'],[1,2,3]], names=['group','id'])

# 3. set_index — most common
df = df.set_index(['year', 'month']).sort_index()  # ALWAYS sort_index()
Selecting data — loc, xs, IndexSlice
Know your selector for each case
# Outer level
df.loc['A']                              # all rows where level-0 == 'A'

# Both levels
df.loc[('A', 2024)]                      # exact row

# xs: best for inner levels (cannot do with loc easily)
df.xs(2024, level='year')              # all rows where year==2024
df.xs(('A',2024), level=['group','year'])

# IndexSlice: range slicing across levels
idx = pd.IndexSlice
df.loc[idx['A':'B', 2022:2024], :]    # groups A-B, years 2022-2024
Stack / Unstack — the power move
unstack pivots an index level into columnsKEY OPERATION
df = df.set_index(['region', 'year'])

# Move 'year' from index → column headers
wide = df.unstack('year')    # columns become MultiIndex (metric, year)

# Reverse: collapse column level back into index
long = wide.stack('year')

# Real use: year-over-year % change per region in 2 lines
sales = df['sales'].unstack('year')
yoy   = sales.pct_change(axis=1) * 100
Pitfalls
⚠ Unsorted index = silent wrong results. After set_index, always call sort_index(). Slicing an unsorted MultiIndex raises PerformanceWarning and returns garbage.

⚠ reset_index() to escape. When MultiIndex becomes unwieldy, flatten it. That's not defeat — that's pragmatism.

Advanced GroupBy
You know groupby().sum(). Now learn the parts that separate analysts from engineers.
Named aggregations — the right way
Named agg: clean output column names, no MultiIndex mess
# Old way: generates ugly MultiIndex columns you have to flatten
df.groupby('dept')['salary'].agg(['mean', 'max', 'count'])

# Named agg (pandas 0.25+) — explicit output names
result = df.groupby('dept').agg(
    avg_salary  = ('salary',      'mean'),
    max_salary  = ('salary',      'max'),
    headcount   = ('employee_id', 'count'),
    total_bonus = ('bonus',       'sum'),
    any_remote  = ('is_remote',   'any'),
)
filter() — prune entire groups
Drop or keep whole groups based on a group-level condition
# Keep only departments with more than 5 employees
df.groupby('dept').filter(lambda x: len(x) > 5)

# Keep groups where mean salary exceeds 70k
df.groupby('dept').filter(lambda x: x['salary'].mean() > 70_000)
apply() — escape hatch, not default tool
Custom per-group logic when nothing else worksSLOW — LAST RESORT
def minmax_scale(group):
    mn, mx = group['salary'].min(), group['salary'].max()
    group = group.copy()
    group['salary_norm'] = (group['salary'] - mn) / (mx - mn)
    return group

result = df.groupby('dept', group_keys=False).apply(minmax_scale)
# group_keys=False: prevents adding group keys to the index
# If apply can be replaced by transform — always replace it. 10-100x faster.
Grouping by bins, booleans, multiple keys
Beyond column names
# Group by derived boolean — no column needed
df.groupby(df['salary'] > 80_000)['bonus'].mean()

# Group by bins
df.groupby(pd.cut(df['age'], bins=[20,30,40,50,60]))['salary'].mean()

# Multiple keys + unstack = quick pivot table
df.groupby(['dept', 'year'])['salary'].mean().unstack()

# observed=True — critical for categorical keys (suppresses empty groups)
df.groupby('dept', observed=True)['salary'].mean()

Performance Optimization
Your code is correct but takes 40 seconds on 1M rows. That's not a Pandas problem. That's a you problem.
Speed hierarchy — know where you sit
MethodRelative SpeedUse When
Built-in vectorized ops⚡ Fastest (baseline)Always try first
NumPy ufuncs on .values⚡ ~baselineMath-heavy operations
Cython-backed groupby agg⚡ ~2-5x slowerGroupby with built-in funcs

.apply(lambda)🔴 ~50-500x slowerLast resort only
Python loop over rows🔴 ~1000x slowerNever.
dtype optimization — do this before anything else
Cut memory and operations get faster automaticallyDO THIS FIRST
# Audit dtypes immediately after loading
df.info(memory_usage='deep')

# int64 is almost always overkill
df['age']  = df['age'].astype('int8')    # 8x reduction
df['year'] = df['year'].astype('int16')

# float64 -> float32 (halve float memory)
fcols = df.select_dtypes('float64').columns
df[fcols] = df[fcols].astype('float32')

# Low-cardinality strings -> category
df['dept'] = df['dept'].astype('category')
query() and eval() — bypass Python overhead
Single-pass filtering and column creation
# Standard: creates 2 boolean arrays then combines them
mask = (df['salary'] > 60_000) & (df['dept'] == 'Engineering')

# query(): single pass, less memory, more readable
df.query('salary > 60_000 and dept == "Engineering"')

# Reference Python variables with @
threshold = 60_000
df.query('salary > @threshold')

# eval() for column creation (avoids temp arrays)
df.eval('bonus_ratio = bonus / salary', inplace=True)

Vectorization vs Apply
apply() is a trap. It feels flexible. It is slow. You will use it as a crutch and I will not allow that.
The Rule
Never use apply() if you can express the operation as:
arithmetic (+,-,*,/), comparison (<,>,==), string methods (.str.*), datetime methods (.dt.*), np.where, np.select, or any built-in aggregation. That covers 90% of what people use apply() for.
Replace apply with np.where / np.select
❌ apply for conditional logicSLOW
df['tier'] = df['salary'].apply(
    lambda x: 'high' if x > 100_000 else ('mid' if x > 60_000 else 'low')
)
✓ np.select for multi-condition logic~100x FASTER
import numpy as np

conditions = [df['salary'] > 100_000, df['salary'] > 60_000]
choices    = ['high', 'mid']
df['tier']  = np.select(conditions, choices, default='low')
String operations — .str. not apply
❌ Python string methods via applyWRONG
df['name_upper'] = df['name'].apply(lambda x: x.upper().strip())
df['has_dr']     = df['name'].apply(lambda x: x.startswith('Dr'))
✓ Vectorized .str accessorCORRECT
df['name_upper'] = df['name'].str.upper().str.strip()
df['has_dr']     = df['name'].str.startswith('Dr')
df['domain']     = df['email'].str.extract(r'@(.+)')[0]  # regex extract
When apply IS acceptable
Legitimate apply use cases:
- Multi-column logic that cannot be expressed with vectorized arithmetic
- Calling external APIs/functions per row (parallelize with joblib though)
- Complex group-level logic in groupby.apply where transform truly won't work

Even then — profile it first. >5s on 100k rows means look harder for a vectorized path.

Large Dataset Handling
When data no longer fits in RAM, most people give up. You will chunk it, compress it, or hand it to the right tool.
Load only what you need
Column selection + dtype hints + chunked reads
# Only load needed columns
df = pd.read_csv('big.csv', usecols=['id', 'date', 'amount'])

# Specify dtypes upfront — avoids expensive inference
dtypes = {'id': 'int32', 'amount': 'float32', 'dept': 'category'}
df = pd.read_csv('big.csv', dtype=dtypes, parse_dates=['date'])

# Chunked processing — never loads full file into memory
results = []
for chunk in pd.read_csv('big.csv', chunksize=100_000):
    agg = chunk.query('amount > 1000').groupby('dept')['amount'].sum()
    results.append(agg)

final = pd.concat(results).groupby(level=0).sum()
Use Parquet not CSV for anything over 100MB
Parquet wins on every axis: size, speed, type fidelityPRODUCTION STANDARD
df.to_parquet('data.parquet', compression='snappy')

# Column-selective read — only loads columns you ask for
df = pd.read_parquet('data.parquet', columns=['id', 'amount'])

# snappy = fast decompress | zstd = better compression ratio
# dtypes are preserved. No re-parsing strings. No inference. Just right.

TOPIC 07 / 10
Method Chaining Pipelines
Stop creating df1, df2, df_final, df_final2. Chain your transformations. One pipeline, one story.
Philosophy
Method chaining: Every Pandas operation returns a DataFrame. Chain them with no intermediate variables. One pipeline = one readable, debuggable transformation story. Read it top-to-bottom like prose.
Core chaining pattern
assign, pipe, query, rename — your chain toolkit
result = (
    pd.read_parquet('sales.parquet')
    .query('year == 2024 and region != "Unknown"')
    .assign(
        revenue = lambda df: df['units'] * df['price'],
        month   = lambda df: df['date'].dt.month,
        is_q4   = lambda df: df['month'] >= 10,
    )
    .rename(columns={'cust_id': 'customer_id'})
    .groupby(['region', 'month'], as_index=False)
    .agg(total_rev=('revenue', 'sum'), orders=('customer_id', 'nunique'))
    .sort_values('total_rev', ascending=False)
    .reset_index(drop=True)
)
pipe() — inject custom functions into chains
Custom logic stays inside the chainELEGANT
def drop_outliers(df, col, z=3):
    mean, std = df[col].mean(), df[col].std()
    return df[(df[col] - mean).abs() <= z * std]

def add_pct_rank(df, col):
    return df.assign(**{f'{col}_pct': df[col].rank(pct=True)})

result = (
    df
    .pipe(drop_outliers, col='salary', z=2.5)
    .pipe(add_pct_rank, col='salary')
    .query('salary_pct > 0.5')
)
Debug chains without breaking them
Tap into the chain with pipe + print — zero disruption
def debug_shape(df, label=''):
    print(f"[{label}] shape: {df.shape}")
    return df  # pass through unchanged

result = (
    df
    .query('salary > 50_000')
    .pipe(debug_shape, 'after filter')
    .groupby('dept').agg(avg=('salary', 'mean'))
    .pipe(debug_shape, 'after agg')
)

Advanced Reshaping
melt, pivot, pivot_table, stack, unstack, explode. Know exactly when to reach for each one. No guessing.
Decision guide
WIDE → LONG
melt() — turn column headers into row values. "Unpivot"
LONG → WIDE
pivot() — unique values become column headers. No aggregation.
AGGREGATED PIVOT
pivot_table() — like pivot but handles duplicates via aggfunc
LISTS IN CELLS
explode() — one row per list element
INDEX → COLUMN
unstack() / stack() — move index levels to columns and back

Categoricals & Memory
Storing "Engineering" as a string 500,000 times when there are 8 departments is a moral failure.
How categoricals work under the hood
Categorical dtype stores: (1) an integer codes array — one int per row, (2) a tiny lookup of unique values. "Engineering" repeated 500k times becomes one integer per row + one string in an 8-item lookup. Memory drops 5–50x depending on cardinality.
Full categorical API
Creating, inspecting, and manipulating categoricals
# Basic conversion
df['dept'] = df['dept'].astype('category')

# Ordered categories — enables <> comparisons and correct sorting
size_dtype = pd.CategoricalDtype(
    categories=['small', 'medium', 'large'],
    ordered=True
)
df['size'] = df['size'].astype(size_dtype)
df[df['size'] > 'small']   # comparison works because ordered=True

# Inspect
df['dept'].cat.categories     # Index of unique values
df['dept'].cat.codes           # int array (the actual storage)

# Mutate categories
df['dept'] = df['dept'].cat.rename_categories({'Eng': 'Engineering'})
df['dept'] = df['dept'].cat.add_categories('Legal')   # before assigning new values
df['dept'] = df['dept'].cat.remove_unused_categories()
Reusable memory optimization function
Systematic dtype optimizer — use on every DataFrame you loadREUSABLE
def optimize_df(df):
    before = df.memory_usage(deep=True).sum() / 1e6

    for col in df.select_dtypes('int64').columns:
        df[col] = pd.to_numeric(df[col], downcast='integer')

    for col in df.select_dtypes('float64').columns:
        df[col] = pd.to_numeric(df[col], downcast='float')

    for col in df.select_dtypes('object').columns:
        if df[col].nunique() / len(df) < 0.5:  # <50% unique values
            df[col] = df[col].astype('category')

    after = df.memory_usage(deep=True).sum() / 1e6
    print(f"Memory: {before:.1f}MB → {after:.1f}MB ({(1-after/before)*100:.0f}% saved)")
    return df

Custom Aggregations
When sum/mean/count aren't enough. Write your own agg functions without surrendering to slow apply().
Named agg with custom callables
Pass any callable directly to agg()
def iqr(x): return x.quantile(0.75) - x.quantile(0.25)
def p95(x): return x.quantile(0.95)
def cv(x):  return x.std() / x.mean()   # coefficient of variation

result = df.groupby('dept').agg(
    mean_sal   = ('salary', 'mean'),
    median_sal = ('salary', 'median'),
    iqr_sal    = ('salary', iqr),    # custom!
    p95_sal    = ('salary', p95),
    cv_sal     = ('salary', cv),
)
Different aggs per column
Dict mapping + flatten the MultiIndex result
result = df.groupby('dept').agg({
    'salary': ['mean', 'max', iqr],
    'bonus':  ['sum', 'mean'],
    'tenure': ['median', p95],
})

# Flatten the MultiIndex columns it generates
result.columns = ['_'.join(col).strip() for col in result.columns]
Rolling custom agg — the one valid rolling apply
raw=True is critical — passes numpy array, not SeriesVALID APPLY USE
def rolling_iqr(arr):   # arr is a numpy array when raw=True
    return np.percentile(arr, 75) - np.percentile(arr, 25)

df['vol_iqr_30'] = df['price'].rolling(30).apply(rolling_iqr, raw=True)
# raw=True: ~3x faster than raw=False (no Series overhead)
